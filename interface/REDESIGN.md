# Web UI redesign

Working plan for moving the web UI to the new design. This file is the source of truth for progress: update it in the same commit as the work, so both machines (and any agent) see the current state after a `git pull`.

- Branch: `webui-redesign` on `origin` (proddy/EMS-ESP32), based on `dev`
- Visual spec: the mockups, hosted at <https://emsesp-mockups.emsesp.org>
- Step IDs (`S2.3` etc.) are used in commit messages and PR titles, for example `webui: status overview (S2.1)`

## Context (read first)

Findings from the analysis, so a new session doesn't have to rediscover them.

**Current UI**

- Preact runs through `preact/compat`. `react` is aliased to `src/preact-react-shim.ts` in `vite.config.ts` (react-router v8 needs `useOptimistic`). Keep that.
- Routes: `src/index.tsx` (react-router v8, `RequireAuthenticated`, `RequireAdmin`) renders the route table in `src/app/routes.tsx`. Since S1.1 the drawer (`LayoutDrawer`) and app bar (`LayoutAppBar`) read the same table; pages no longer set their own title.
- REST: alova in `src/api/endpoints.ts` (bearer token, `PASSWORD_REQUIRED` re-prompt via `passwordPrompt.ts`, MessagePack unpack for `arraybuffer` responses). Calls per area in `src/api/*.ts`.
- Settings forms use `src/utils/useRest.ts`: keeps `origData`, `dirtyFlags`, `useBlocker` for the unsaved-changes guard, and handles the 205 "Reboot required" response. The new save bar should sit on top of this, not replace it.
- No `o_*` copies are left: Scheduler, Commands, Custom Entities and Modules use `usePendingList` (S5.1); Customizations keeps the loaded entities in a `Map`.
- Theme: was `src/CustomTheme.tsx` (MUI dark theme, font size 13), removed in S7.1/S7.3; styling is now `components/ui/tokens.css` + `base.css`. Shared components: `src/components/ui` plus `layout`, `routing`, `toast`. The recovery app (`src/recovery`) uses the same ui components with `recovery/UiText.tsx` (English-only `LL`) and `recovery/icons.ts` (its own icon subset via the `recoveryIcons()` Vite plugin).
- i18n: typesafe-i18n, `LL.*` keys, `src/i18n/<lang>/index.ts`.
- `deviceValue.ts` `formatValue(LL, value, uom)` is the shared value formatter. The firmware sends temperature sensor offsets already converted to °F when Fahrenheit is on (`u = FAHRENHEIT`). `NAME_PATTERN` allows no spaces, so mock names like "Dallas 1" fail validation on save.
- Device values: the firmware only sends `c` (command) for values that have a command and aren't write-disabled, so a value without `c` that is writeable was write-disabled in Customizations. `formatValue` returns '' for `null` (a sensor without a reading used to show "null °C").
- `ScheduleFlag`: days in bits 0-6 (Sunday = 1, 127 = every day), TIMER 128, ONCHANGE 129, CONDITION 130; no "immediate" type. A timer with empty or 00:00 time runs once at start-up. All types store their value in `time`. `.wrap` is a global utility class (`flex-wrap: wrap`); don't reuse the name. `LL.TYPE` takes an argument (Polish plural).
- `systemStatus.partitions` only lists app partitions that pass image verification (no recovery); the factory partition is labelled `boot` on 16/32 MB. The mock also sends a `factory` entry; the page filters `boot`/`factory`. Mock presets: `/rest/mockVersions?preset=N` (`reset=1` for defaults; 7 = firmware + recovery update, 11 = offline, 12 = 4 MB board).
- Firmware tests: `pio test -e native` has no Unity setup; use `pio run -e native-test -t exec` (159 tests). "Writable" entities include active-control values (`selflowtemp`) and energy counters, so a heating restore must not write everything blindly.
- Browser automation: `browser_fill` doesn't trigger Preact's `onInput`; set the value and dispatch an `input` event via `Runtime.evaluate`.
- Before the redesign MUI was imported in 79 files, about 393 `sx` props, MUI icons in 58 files, `@table-library` in 11, `react-icons` in 3.
- Biggest pages: ApplicationSettings 1147 lines, Version 1045, Customizations 955, Devices 834, Recovery Dashboard 630.

**Icons**

The mockups use Material Symbols Rounded by name (`<span class="ms">name</span>`). Copy each used icon as SVG from `google/material-design-icons` (`symbols/web/<name>/materialsymbolsrounded/<name>_24px.svg`) or the `@material-symbols/svg-400` package, keep only the path data, and register it in `components/ui/icons/`. No font, no CDN.

Some ligature names in the mockups are legacy aliases with no folder of their own in that repo (`assessment` is `insert_chart`, `sd_storage` is `sd_card`). Look the name up in `variablefont/MaterialSymbolsRounded[FILL,GRAD,opsz,wght].codepoints` and fetch the canonical name with the same codepoint; the file keeps the mockup name.

**Build**

- The production and recovery builds set `treeshake.moduleSideEffects: false`. A module none of whose exports are used is dropped together with its side-effect imports, so a `import './x.css'` in the `components/ui` barrel never reaches the bundle. CSS imported by a component that is used (`Icon.tsx` imports `Icon.css`) is kept. Global CSS (`tokens.css`, `base.css`) has to be imported from the entry `src/index.tsx`.
- Routes come from `src/app/routes.tsx` (`routes`, `renderRoute`, plus `findRoute`, `routeTrail`, `menuRoutes` for the drawer and breadcrumbs). `src/index.tsx` only keeps sign-in, the redirects, the auth/admin wrappers, the catch-all and the dev-only `/ui` gallery (`components/ui/gallery/`). Add a page by adding a row to the table.
- `eslint.config.js` makes `@mui/*`, `@emotion/*`, `react-icons` and `@table-library/*` imports an error in all of `src/**` (the packages are no longer installed).
- `components/layout` is no longer re-exported from the `components` barrel: Layout imports the route table, which imports the pages, which import `components`, so the re-export made a cycle. Import it from `components/layout`.
- Shell (S1): `Layout.tsx` renders `.shell` with the drawer, a scrim, the app bar and `<main>`; at the end of `<main>` sits `.savebar-slot`, passed down through `SaveBarSlotContext`. `<SaveBar>` portals into it (inline when there is no provider, as in the gallery). Z-order: drawer 1200, scrim 1150, app bar 1100; dialogs and the toaster use the browser top layer.
- Browser testing with the Cursor browser tools: their key presses are synthetic, so Enter doesn't submit a form and Escape doesn't close a native `<dialog>` (both work with a real keyboard). Dispatch a `cancel` event on the dialog to test Escape handling. Screenshots often show the frame before the last action; take a second one.
- Status pages (S2): `app/status/status.ts` maps each status code to a `{ state, text }` pair (`ok` / `warn` / `err` / `off`, the same states as `Hero`, `Tile`, `StatusDot` and `Chip`) and holds `formatDuration` and `nf`. `StatusPage.tsx` is the hero + optional extras + Details layout used by Network, MQTT, NTP and Access Point. Page layout CSS lives in `app/status/Status.css` and `SystemLog.css` with `st-` / `log-` prefixes. `SystemMonitor` (used by six pages for restarts and firmware installs) keeps its `onDone` / `onInstallCustom` props.
- The i18n base locale in `.typesafe-i18n.json` is `pl`, so generated parameter types come from the Polish strings. Plurals with six forms (`{{zero|one|two|few|many|other}}`, as in cs, sk and pl) parse; full words work as forms, e.g. `'{num} {{chyb|chyba|chyby|chyby|chyb|chyb}}'`.
- Firmware: `WebLogService` counts errors and warnings in `operator<<`, so only messages at or above the current log level are counted. `Network::getIP()` returns the IPv4 address on WiFi or Ethernet, empty when not connected.
- `pnpm standalone` runs Vite on port 3000 with the mock API on 3080 (users `admin`/`admin` and `guest`/`guest`). The Cursor browser runs on Windows and reaches WSL's `localhost` ports directly.
- CI: `dev_release.yml` builds the web UI only on upstream `dev` when `src/emsesp_version.h` changes, and `pr_check.yml` ignores `interface/`. `webui_check.yml` (S0.5) covers `interface/` changes on PRs to `dev` and pushes to `dev` (the `webui-redesign` push trigger was dropped in S7.5). The i18n types are gitignored and generated by `typesafe-i18n`, so in CI the build has to run before lint and `tsc`.
- Settings forms (S4): `app/settings/FormPage.tsx` (`useFormPage` + `<FormPage form>{(data) => ...}</FormPage>`) is the page frame for every settings object; field props come from `utils/formFields.ts`. List pages (S5): `utils/usePendingList.ts` + `app/main/ListPage.tsx` + `app/main/EntityDialog.tsx`. Both use the `SaveBar`; pages don't add their own Apply buttons.
- `extractEventValue` (utils/binding) keeps partly typed numbers ("1.", "-") as strings so the caret doesn't jump; `formFields().number()` relies on it, so a number field's value can briefly be a string and validators must allow for that.
- `progmem-generator.js` compresses each asset with zopfli; the sizes stored in `src/ESP32React/WWWData.h` (gitignored, generated) are what ends up in flash. Run `node progmem-generator.js` after `pnpm build` to regenerate it.

**Firmware already supports** (no change needed): hashed API keys shown once on create (`/rest/apiKeys`), `auto_fw_check`, `write_limit` / `write_limit_refuse`, GPIO lists in sensor and settings data, `setPartition` / `getVersions` / `uploadURL` / `recovery_version`, `/rest/console`, `/rest/logSettings`, `/rest/time`, product ID per device in `/rest/coreData` (`p`), all export types except `heatingbackup`.

## Goals

- Look and behave like the mockups
- **Smaller flash**: no `@mui/*` or `@emotion/*` at the end, local SVG icons only (no icon fonts, no CDN), fewer third-party libraries
- **Responsive**: phone (360 px and up), tablet and desktop
- No regressions in behaviour: auth and admin gating, unsaved-changes guard, password re-prompt, i18n for every language, MessagePack endpoints
- Keep page URLs unchanged (bookmarks and firmware redirects such as `/fileUpdated` depend on them)

## Rules

- Pages import UI only from `components/ui`, never from `@mui` directly. An ESLint `no-restricted-imports` rule enforces this per migrated folder.
- Icons: one `Icon` component backed by local SVG files in `components/ui/icons/`, only the icons actually used. Material Symbols Rounded, 24 px, copied in as SVG paths.
- Styling: plain CSS with the tokens from `components/ui/tokens.css` (taken from `mockups/base.css`). No CSS-in-JS.
- Every new UI string goes into all `src/i18n/<lang>/index.ts` files.
- Any REST change: update `mock-api/restServer.ts` in the same commit.
- Each step ends with `pnpm lint`, `pnpm build`, a bundle size entry in the table below, and a check on a phone-sized viewport.

## Responsive rules

| Width | Layout |
| --- | --- |
| < 600 px (phone) | Drawer is an overlay opened from the app bar. Tables with many columns turn into stacked cards. Dialogs are full screen. Save bar spans the full width at the bottom. Form fields in one column. |
| 600-1199 px (tablet) | Drawer is an overlay, or collapses to icons from 900 px. Two-column forms and tile grids. |
| >= 1200 px (desktop) | Fixed drawer, as in the mockups. |

Touch targets at least 40 px, no hover-only actions, inputs at least 16 px font on iOS (avoids zoom on focus).

## Decisions

Short log of choices made along the way, newest last.

- 2026-11-18: Migrate inside `interface/` page by page, no separate Preact port of the mockups.
- 2026-11-18: Own component library with plain CSS and local SVG icons; MUI only as a temporary backend for complex components.
- 2026-11-18: Cursor rule `.cursor/rules/webui-redesign.mdc` (force-added, `.cursor` is gitignored) makes every session read this file and record decisions. Branch-only.
- 2026-11-18: Icons are one SVG file per icon in `components/ui/icons/` (viewBox `0 -960 960 960` and a single path), imported with `?raw` and listed in `icons/index.ts`; `IconName` is the key type, so an unknown name fails type checking. File names are the mockup ligature names. (S0.1)
- 2026-11-18: `Icon` API is `<Icon name size? className? label? />`. `size` is `sm` (18 px) or `xs` (16 px), default 22 px like `.ms`. Other sizes come from parent CSS (`.hero-icon .icon { font-size: 28px }`), the same way the mockup CSS sizes `.ms`. Decorative (`aria-hidden`) unless `label` is given. (S0.1)
- 2026-11-18: Only outlined icons for now; filled variants (`.ms.fill`) are added as `<name>_fill.svg` when a page needs one. (S0.1)
- 2026-11-18: Mockup class names stay unprefixed (`.row`, `.cap`, `.muted`; `.icon` replaces `.ms`). Nothing in `src/` uses `className` today, so there are no clashes with the MUI pages during the migration. (S0.1)
- 2026-11-18: `tokens.css` is the mockup `:root` block plus `--font`, `--font-mono`, `--font-size` and `--appbar-h`. `base.css` holds only element resets, a `:focus-visible` ring, 16 px input font below 600 px, and layout/text utilities. Component styles live next to their component (`Icon.css`) and arrive with their own step. No `@font-face`: Roboto stays in `public/css/roboto.css`. (S0.1)
- 2026-11-18: `tokens.css` and `base.css` are not imported anywhere yet, so nothing changes visually. S1.1 imports them from `src/index.tsx` (not from the `components/ui` barrel, see Build under Context). (S0.1)
- 2026-11-18: Flash budget JS sizes are the zopfli sizes from `WWWData.h`, because that is what goes into flash; the baseline JS figures couldn't be reproduced with any gzip method. (S0.1)
- 2026-11-18: Gallery is a lazy route at `/ui` behind `import.meta.env.DEV`, outside the sign-in guard, in `components/ui/gallery/`. Its page layout CSS uses a `gal-` prefix to stay apart from component classes. It imports `tokens.css` and `base.css` itself, so in dev they apply to the whole app after visiting `/ui` until the page is reloaded. (S0.2)
- 2026-11-18: Route table lives in `src/app/routes.tsx`. `title` is a function of `LL`, not a key name, because several titles take arguments (`LL.NETWORK(1)`) or are plain strings. Other fields: `icon`, `parent` (path), `admin`, `badge: 'update'`, `menu` (drawer group `main`/`modules`/`system`/`account`, in table order), `wildcard` (adds `/*`), `children` (nested tab routes as JSX).
